# ADR-0006：领域模型推迟到阶段 2，和 Broker 接口一起设计

- 状态：✅ 已采纳
- 日期：2026-11-03

## 背景

计划的 P1-06 要在阶段 1 做好 `maq-core` 的领域模型（Bar、Order、Position……）、事件定义和时钟抽象。

## 决定

阶段 1 的 `maq-core` 只放眼下马上会用到的东西：配置 schema 和结构化日志。领域模型、事件和时钟放到阶段 2，和第一个使用它们的地方——`Broker` 协议、契约测试、`SnapshotBuilder` 的 `as_of` 约束——一起设计。

## 理由

脱离使用场景空设计的模型，几乎一定要返工；而 `Broker` 接口一落地，就能看清楚 `Position`、`OrderRequest` 到底需要哪些字段。

## 后果

- 阶段 1 的验收里去掉"领域模型有完整单测"这一条，移到阶段 2 的 P2-01。
- 现在的测试替身（`tests/fakes/mt5.py`）是在 MT5 API 层面做的模拟，阶段 2 的 `FakeBroker` 会在它之上实现。
