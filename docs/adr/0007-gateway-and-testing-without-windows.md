# ADR-0007：MT5 Gateway 用 REST + 长轮询；没有 Windows 时用模拟交易服务器验证

- 状态：✅ 已采纳
- 日期：2026-11-03

## 背景

ADR-0004 定了"Windows 上只跑一个很薄的 Gateway，其余部分跑在任意平台"。拍板时又补充了一条：**眼下不在 Windows 上跑**。可是 MT5 适配器和 Gateway 又必须现在就写好、而且要有把握，不能等到上了 Windows 才发现翻译层（请求字段、返回码、成交记录）有问题。

计划里 Gateway 写的是"REST + WebSocket"。

## 决定

1. **事件推送用长轮询，不用 WebSocket。** `GET /events?after=<序号>&wait=<秒>`：有新事件立刻返回，没有就最多等 `wait` 秒。好处是每个请求都是普通的 HTTP 请求，断线重连就是"再发一次"，穿过代理和 SSH 隧道也不出问题；客户端靠序号续读，不会漏事件。实时性对我们足够（15 分钟一轮的策略，秒级延迟无所谓）。
2. **事件从成交记录（deal history）里推导**，而不是从下单的返回值里拼。这样服务器端触发的止损止盈、手动在终端里平的仓、挂单成交，全都能看到；重启后先把已有成交标记为"旧的"，不会重放。
3. **幂等键放进订单 comment**（31 个字符以内）。重发同一个键之前先按 comment 查历史订单；部分券商会截短 comment，所以 12 个字符以上的前缀也算匹配。
4. **没有 Windows 时，用一个模拟交易服务器（`tests/fakes/mt5_server.py`）验证适配器。** 它在 `MetaTrader5` 的 API 层面模拟一个对冲账户：校验手数步长、filling 类型、止损距离、滑点、保证金，按真实返回码作答，像 MT5 一样记历史订单和成交（持仓号 = 开仓订单号，`entry` 区分开平，`reason` 区分 EA / 止损 / 止盈）。它**和 `PaperBroker` 是两套独立实现**。
5. **同一套契约测试跑三条链路**：`PaperBroker`；`Mt5Broker` + 模拟服务器；客户端 → HTTP → Gateway → `Mt5Broker` + 模拟服务器。三条链路行为一致，才算过。

## 后果

- 好处：现在就能在 Linux 上把 MT5 这一侧改到有把握；两套独立实现互相印证，比只测一边更容易发现误解。
- 代价：模拟服务器毕竟不是真服务器。真实券商的差异（市价执行模式忽略 `deviation`、comment 被改写、服务器时区、部分成交）只能等上了模拟盘再看。依赖真实终端的验收项（P2-02 的"24 小时不掉线"、P2-03 的"模拟盘上契约测试全过"）顺延。
- 以后接 cTrader / OANDA 等券商时，同样实现 `Broker` 接口、跑同一套契约测试即可。
