# ADR-0005：配置——保留 7 个 YAML，加类型校验和环境变量覆盖

- 状态：✅ 已采纳
- 日期：2026-11-03

## 背景

7 个 YAML 配置没有任何校验：键名拼错（比如 `enforcment:`）会静默失效，代码回落到默认值；风险参数也可以随便写成 0.5（单笔 50%）。另外 MT5 终端路径这种"每台机器不一样"的值只能改受版本控制的文件。

计划（P1-07）原本设想把 7 个文件合成一个新格式的配置。动手时发现：30 多处调用 `load_yaml(...)` 再 `cfg.get(key, default)`，一次性迁移风险大、收益小。

## 决定

1. **格式不变**，在 `maq_core.config` 里给每个文件写一份严格的 Pydantic schema：未知键报错、数值范围检查、跨字段规则（阈值顺序、权重只能给已列出的模型、回撤降仓系数只能越来越小等）。
2. **硬上限写在代码里**，配置只能往紧了调：单笔风险 ≤ 2%、当日亏损上限 ≤ 10%、回撤熔断 ≤ 50%。
3. **环境变量覆盖**：`MAQ_<文件>__<键>__<子键>=值`，比如 `MAQ_TOOL__MT5__TERMINAL_PATH`。覆盖值同样要过校验。
4. **对旧代码透明**：`tools/config_loader.load_yaml` 对这 7 个文件做校验并应用覆盖，但只返回"文件里写了或被覆盖了"的键，旧代码的 `cfg.get(key, default)` 默认值保持不变。
5. **实盘门槛**：`live_trading_issues()` 列出不适合实盘的设置，`run_loop.py --live` 遇到就拒绝启动。
6. **逃生口**：`MAQ_CONFIG_STRICT=0` 时校验失败只告警，返回原始内容。schema 稳定后删掉。

没有用 pydantic-settings：它的优先级是"代码传参 > 环境变量 > 文件"，和我们要的"环境变量 > 文件"相反，自己写 30 行的合并逻辑反而更清楚。

## 后果

- 任何一个配置写错，`run_loop.py` 启动时就会列出所有问题并退出（返回码 2），`maq config validate` 也能单独检查。
- 合并成单文件的事推迟到阶段 4 新编排器上线时，届时旧代码不再直接读 YAML。
